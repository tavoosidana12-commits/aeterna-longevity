# AETERNA — پرتال گزارش آزمایش و پایش سلامت (Next.js + PostgreSQL)

پلتفرم ثبت آزمایش‌های طول عمر توسط مدیر، تحلیل خودکار، تولید نمودارها، دسترسی بیمار از طریق **QR Code** و **چاپ لوکس** گزارش.

## صفحات و مسیرها

| مسیر | توضیح |
|---|---|
| `/` | صفحه اصلی سایت |
| `/admin` | پنل مدیریت: ورود اطلاعات بیمار و نتایج آزمایش (فرم کامل نشانگرهای زیستی، ژنتیک، یادداشت پزشک) |
| `/portal/[accessCode]` | پورتال موبایل‌فرندلی بیمار با نمودارها و تحلیل (دسترسی با کد اختصاصی) |
| `/print/[accessCode]` | نسخه لوکس و آماده چاپ گزارش (A4، استایل اختصاصی + دکمه چاپ) |
| `/api/report/patients` | فهرست بیماران (JSON) — استفاده در فرم ادمین |
| `/api/report/[accessCode]` | گزارش کامل یک بیمار (JSON) |
| `/api/qr/[accessCode]` | تصویر **QR Code** (SVG، بدون وابستگی خارجی) که به پورتال بیمار لینک می‌دهد |
| `/api/health` | بررسی سلامت سرویس |
| `/secure-analysis` | تحلیل هوش مصنوعی Grounded (RAG) با جلوگیری از پاسخ خارج از دانش‌پایه |

## گردش‌کار مدیر (Admin Workflow)

1. ورود به `/admin` و انتخاب «بیمار جدید» یا «بیمار موجود» (لیست از API خوانده می‌شود).
2. تکمیل مشخصات، سن تقویمی، نتایج آزمایش‌ها (گلوکز، انسولین، HbA1c، چربی‌ها، ApoB، Lp(a)، hs-CRP، NAD+، کورتیزول، VO2Max، ...) و پروفایل ژنتیکی.
3. زدن «ذخیره و تولید گزارش» — Server Action نتایج را در PostgreSQL (یا حافظه در حالت دمو) ذخیره و **کد اختصاصی** (مثل `AET-1234-K`) تولید می‌کند.
4. لینک‌های پورتال مشتری و نسخه پرینت بلافاصله نمایش داده می‌شوند.
5. QR Code پورتال از `/api/qr/<accessCode>` قابل دریافت و چاپ است.

> سازگاری React 18: فرم ادمین از `useFormState` (از `react-dom`) استفاده می‌کند. برای ارتقا به React 19 کافی است به `useActionState` (از `react`) تغییر کند.

## لایه داده (src/lib/store.ts)

- اگر `DATABASE_URL` تنظیم شده باشد، همهٔ خواندن/نوشتن از طریق `sql` در `src/lib/db.ts` به **PostgreSQL** انجام می‌شود (جداول `aeterna.patients` و `aeterna.lab_panels`).
- اگر `DATABASE_URL` تنظیم **نشده باشد** یا اتصال شکست بخورد، سیستم به‌صورت شفاف به **Map درون‌حافظه** فالبک می‌کند؛ پروژه بدون دیتابیس هم اجرا می‌شود (`dbMode()` وضعیت فعلی را برمی‌گرداند).
- داده‌ها در حالت Postgres همیشه ابتدا در کش حافظه‌ای همان نمونه نیز mirror می‌شوند تا پاسخ‌دهی سریع بماند.

## مهاجرت اسکیما (DB Migration)

روی دیتابیس لیارا یک‌بار اجرا کنید:

```bash
psql "$DATABASE_URL" -f sql/schema.sql
```

شامل: extension `vector`، اسکیمای `aeterna`، جداول `patients`، `lab_panels`، `visits`، `knowledge_base`، `ai_recommendations` و تابع `match_knowledge_base` (جست‌وجوی برداری pgvector).

## اجرا

```bash
npm install
cp .env.example .env.local   # DATABASE_URL (اختیاری) و OPENAI_API_KEY را تنظیم کنید
npm run dev                  # http://localhost:3000
npm run build && npm start   # حالت پروداکشن
```

## استقرار در لیارا

فایل `liara.json` موجود است. متغیرهای محیطی لازم: `DATABASE_URL` (Postgres لیارا)، `OPENAI_API_KEY`. پس از اولین استقرار، `sql/schema.sql` را یک‌بار روی دیتابیس اجرا کنید.
